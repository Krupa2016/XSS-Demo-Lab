Cross-Site Scripting (XSS) Demo Lab

A small, self-contained, offline playground for learning the three classic flavors of XSS: Reflected, Stored, and DOM-based.

⚠️ For learning only. Everything here runs 100% locally in your own browser — there is no real server, no real database, and no real other users. Nothing you type here ever leaves this HTML/JS. Never test payloads like these against websites or systems you don't own or have explicit written permission to test.

How this lab is organized

Each of the three lab pages below follows the same structure:

  • Intro — what this type of XSS is and why it happens.
  • How to perform it — the general attacker mindset and steps, explained conceptually.
  • Hands-on lab — a small intentionally-vulnerable widget you can attack yourself, with a success flag that lights up when you pull it off.
Reflected XSS

Reflected XSS

Payload travels in the request (e.g. a URL parameter) and is echoed straight back into the page's HTML.

 Stored XSS

Stored XSS

Payload is saved (e.g. in a comment) and then rendered unsanitized for every visitor who later views it.

 DOM-based XSS

DOM-based XSS

Payload never touches a server at all — vulnerable client-side JS reads untrusted data (like the URL hash) and writes it straight into the DOM.

What you'll need

Just a browser. Open index.html (this file) directly, or serve the folder with any static file server. No build step, no dependencies, no backend.
